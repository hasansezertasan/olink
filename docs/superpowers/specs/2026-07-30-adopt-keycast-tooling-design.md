# Design: Adopt keycast tooling & configuration into olink

**Date:** 2026-07-30
**Reference repo:** <https://github.com/hasansezertasan/keycast>
**Target repo:** olink (pure-Python CLI published to PyPI)

## Goal

Bring keycast's tooling/configuration improvements into olink, **including removing the
`x-release-please-version` static-version mechanism**. keycast is a more mature project,
but much of its tooling is specific to a GUI app shipped as native binaries
(PyInstaller, MSIX, Inno Setup, Homebrew/Scoop casks, xvfb, tox wheel-testing). Those are
**out of scope**. Only the parts that apply to a pure-Python CLI are adopted.

## Decisions (locked)

| Area | Decision |
| --- | --- |
| Versioning | Migrate to **hatch-vcs** (git tag is the single source of truth) |
| Task runner | **Keep poethepoet** (poe). Do NOT migrate to tox. |
| Extras | Adopt all four: typos CHANGELOG-hash ignore, `.gitattributes`, uv `add-bounds=exact` + exact pins, codecov.yml + coverage upload |
| Find-more | Adopt all: SHA-pin actions, `--frozen`/`--locked` in CI, coverage `exclude_also`, niceties (testpaths, mypy pretty/show_error_codes, CI `workflow_dispatch`), `.vscode/launch.json` |
| CI lint | **Consolidate** ruff/typos/taplo/validate-pyproject into a single `prek run --all-files` job |

## Out of scope (keycast-specific, excluded)

PyInstaller/MSIX/Inno packaging, Homebrew/Scoop bump jobs, xvfb/DISPLAY handling, tox +
tox-uv, the `reconcile`/prerelease multi-channel release machinery, `[tool.hatch.metadata]
allow-direct-references` (olink has no direct-URL deps).

## Section 1 — Versioning migration (hatch-vcs)

Removing `x-release-please-version` means dropping the static version literal entirely and
deriving the version from the git tag, exactly as keycast does.

### 1.1 `pyproject.toml` `[project]`

- Replace `version = "0.1.0" # x-release-please-version` with `dynamic = ["version"]`.

### 1.2 `pyproject.toml` build system + hatch config

- `[build-system].requires`: pin `hatchling` and add `hatch-vcs`
  (e.g. `["hatchling==1.31.0", "hatch-vcs==0.5.0"]` — pin to current known-good).
- Add:

  ```toml
  [tool.hatch.version]
  source = "vcs"
  fallback-version = "0.0.0"

  [tool.hatch.version.raw-options]
  version_scheme = "only-version"
  local_scheme = "no-local-version"

  [tool.hatch.build.hooks.vcs]
  version-file = "src/olink/_version.py"
  ```

- Rationale comments mirror keycast: tag is the source of truth; `fallback-version` keeps
  shallow checkouts from erroring; `only-version` + `no-local-version` keep non-tag builds
  PyPI-uploadable.

### 1.3 `src/olink/__init__.py`

- Replace `__version__ = "0.1.0"` with `from olink._version import __version__`.
- Keep `__all__ = ["__version__"]` and the module docstring.
- `src/olink/_version.py` is **already** gitignored (`.gitignore:330`) and is generated by
  the hatch-vcs build hook on every `uv sync` / build.

### 1.4 `.github/release-please-config.json`

- Remove the `extra-files` block (there is no literal to bump).
- Add `"force-tag-creation": true` (release-please creates the tag eagerly so hatch-vcs can
  read it at build time) and `"bump-minor-pre-major": true` (pre-1.0 breaking changes bump
  minor, not major).

### 1.5 `.github/workflows/release-please.yml`

- Add `with: fetch-depth: 0` to the `publish` job's `actions/checkout` step so hatch-vcs
  sees the full history/tag when running `uv build`.

### 1.6 `tests/cli/test_cli.py`

- `test_version_renders_package_version` (line ~32): update the docstring/comment — it
  currently states "release-please owns `__version__` as a static literal in
  `olink.__init__`". After migration, `__version__` comes from the git tag via hatch-vcs
  (generated `_version.py`). The test **body** (monkeypatch `cli_module.__version__` to
  `"9.9.9"`, assert `--version` echoes it) stays unchanged.

### Versioning acceptance

- `uv sync` regenerates `src/olink/_version.py`; `uv run olink --version` prints the
  hatch-vcs version. On a checkout with no tags it prints `0.0.0` (fallback). `grep -r
  x-release-please-version` returns nothing. `uv build --no-sources` succeeds.

## Section 2 — The four chosen extras

### 2.1 typos CHANGELOG-hash ignore (`pyproject.toml`)

```toml
[tool.typos.default]
# release-please writes commit links like `[9ae107a]` into CHANGELOG.md; the abbreviated
# SHA can read as a word fragment. Ignore the bracketed hash token wholesale.
extend-ignore-re = ["\\[[0-9a-f]{7,40}\\]"]
```

### 2.2 `.gitattributes` (new file)

```
* text=auto eol=lf
```

### 2.3 uv exact bounds + git cache-keys + exact dev pins (`pyproject.toml`)

- `[tool.uv]`: add `add-bounds = "exact"` and

  ```toml
  cache-keys = [
    { file = "pyproject.toml" },
    { git = { commit = true, tags = true } },
  ]
  ```

  (keep existing `trusted-publishing = "always"`).
- Pin currently-loose dev dependencies in the `lint`/`test`/`tool` groups to exact `==`
  versions (resolve each to the version already in `uv.lock`), matching keycast's style.
  Runtime deps (`typer`, `defusedxml`) are already pinned/appropriate.
- Run `uv lock` afterward so the lockfile stays consistent.

### 2.4 codecov + coverage upload

- New `.github/codecov.yml` (keycast's content: project/patch `target: auto`,
  `threshold: 1%`, comment layout, carryforward flags).
- In `.github/workflows/ci.yml` `test` job, add a `codecov/codecov-action` (SHA-pinned)
  step gated on `matrix.os == 'ubuntu-latest'`, uploading `./coverage.xml` with
  `token: ${{ secrets.CODECOV_TOKEN }}`. Requires the test job to emit `coverage.xml`
  (add `--cov-report=xml` or a `coverage xml` step).
- **Note:** reporting only activates once a `CODECOV_TOKEN` repo secret exists; the step is
  harmless without it.

## Section 3 — Find-more items

### 3.1 Pin GitHub Actions to commit SHAs

- In `ci.yml` and `check-pr-title.yml`, replace floating tags (`@v7`, `@v9.0.0`,
  `amannn/action-semantic-pull-request@v6`, etc.) with pinned commit SHAs plus a
  `# vX.Y.Z` comment (release-please.yml already does this). Use the same SHAs keycast
  uses where the action/version matches; otherwise resolve the SHA for the tag currently
  referenced.

### 3.2 `--frozen` / `--locked` in CI

- CI install steps use `uv sync --all-extras --frozen`; tool invocations that go through
  the runner use `uv run --locked ...`. Ensures CI runs against the committed lockfile.

### 3.3 coverage `exclude_also` modernization (`pyproject.toml`)

- Rename `[tool.coverage.report] exclude_lines` → `exclude_also` and add `"\\.\\.\\."`
  (ellipsis bodies) to the existing entries.

### 3.4 Niceties

- `[tool.pytest.ini_options]`: add `testpaths = ["tests"]`.
- `[tool.mypy]`: add `pretty = true` and `show_error_codes = true`.
- `ci.yml`: add `workflow_dispatch:` to the `on:` triggers.

### 3.5 `.vscode/launch.json` (new file)

- Adapt keycast's debugpy config to launch olink via `uv run olink ${input:args}` with a
  prompted-args input (default a harmless target, e.g. `--version`).

## Section 4 — CI restructure (consolidate lint into prek)

Rewrite `.github/workflows/ci.yml` jobs to:

1. **`hooks`** — runs `uv run --locked prek run --all-files --show-diff-on-failure`.
   Replaces the old `lint` job; `prek.toml` already covers ruff, ruff-format, typos, taplo
   (lint+format), validate-pyproject, markdownlint, yamlfmt, plus the builtin file checks.
2. **`test`** — OS matrix (ubuntu/macos/windows), `uv sync --all-extras --frozen`, git
   identity config, run pytest with coverage, emit `coverage.xml`, upload to Codecov on
   ubuntu (§2.4).
3. **`typecheck`** — unchanged matrix (mypy, pyright, ty, pyrefly, pylint, vulture,
   slotscheck), but with SHA-pinned actions and `--frozen`.

`prek.toml` itself is **not** downgraded to keycast's upstream-repo style — olink's builtin
native-hook style is newer and kept as-is.

The old separate `lint` job is removed.

## Verification (whole change)

- `uv sync --all-extras` succeeds; `_version.py` generated.
- `uv run olink --version` prints a version (tag-derived, or `0.0.0` fallback).
- `uv run poe style`, `uv run poe typecheck`, `uv run poe test` all pass locally.
- `uv run prek run --all-files` passes.
- `uv build --no-sources` produces a wheel/sdist with the correct dynamic version.
- `grep -rn "x-release-please-version" .` → no matches.
- `uv run pytest tests/cli/test_cli.py::...::test_version_renders_package_version` passes.
